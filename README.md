# KrisPekt

Рукописные конспекты по предметам: полка с тетрадями, письмо стилусом, PDF и фото, всё — прямо в браузере.

**Открыть приложение:** https://t0n1ks.github.io/KrisPekt/

© 2026 t0n1ks

> **English summary.** KrisPekt is an offline-first web app (PWA) for handwritten notes organised by subject. Write with a stylus (pressure, palm rejection, line straightening), highlight, erase, select with a lasso, add text, photos and PDF pages, and export notebooks as vector PDF, raster PDF or PNG. Everything is stored locally in the browser (IndexedDB); there is no account and no server. Interface languages: Ukrainian, Russian, German and English. Built with TypeScript and Vite, deployed to GitHub Pages by GitHub Actions. The code is proprietary: see [License](#лицензия--license).

## Что умеет

- **Полка:** предметы → тетради с обложками (24 цвета и свой цвет), порядок предметов меняется перетаскиванием за ручку или пунктами «Выше / Ниже», поиск, резервная копия и восстановление, автокопия, корзина на 30 дней, отчёт о занятом месте.
- **Редактор:** ручка с нажимом стилуса и пятью типами (шариковая, перьевая, линер, карандаш, кисть), маркер, палитры на 30 и 12 цветов с недавними цветами и вводом #RRGGBB, до 5 цветов на панели, ластик по точкам или по штрихам (переключается нажатием на активный ластик, работает и кнопка-ластик стилуса), лассо (перемещение, размер, цвет, копия, удаление), текст, фото, линейка, отмена/повтор, касание двумя пальцами — отмена (выключается в ⋯), задержка стилуса — ровная линия, масштаб щипком, листание с инерцией.
- **Ладонь не листает страницу:** см. раздел «Отсечение ладони» ниже. В ⋯ редактора есть «Отмена касанием двумя пальцами» (по умолчанию включена) и «Листать только двумя пальцами» (по умолчанию выключено).
- **Замочек размера страницы:** размер тетради задаётся при создании и хранится в ней самой; новые страницы с замком получают его, без замка — размер предыдущей страницы.
- **Страницы:** кнопка со счётчиком страниц открывает сетку миниатюр. Страницы можно вставлять в любое место, перетаскивать, дублировать и удалять, см. раздел «Страницы тетради» ниже.
- **PDF и PNG:** страницы PDF можно добавить как фон. «Экспорт…» сохраняет тетрадь, текущую страницу или диапазон страниц как векторный PDF, растровый PDF (300/600 dpi) или PNG (2×/4×/6×, несколько страниц — в ZIP).
- **Языки:** українська, русский, Deutsch, English.

## Как установить на телефон или планшет

1. Открой ссылку выше в Chrome (Android) или Safari (iPhone/iPad).
2. Chrome: меню **⋮ → «Добавить на главный экран»** (или «Установить приложение»). Safari: **«Поделиться» → «На экран „Домой“»**.
3. Приложение откроется в отдельном окне и будет работать без интернета.

## Где хранятся данные

- **Все тетради хранятся только в браузере на этом устройстве.** Никуда не отправляются: у приложения нет сервера, аналитики и внешних запросов.
- У каждого человека по ссылке своя полка (сначала с примером тетради). Синхронизации между устройствами нет.
- **Перенос и страховка:** на полке **⋯ → «Сохранить резервную копию»** скачивает файл `krispekt-backup-ГГГГ-ММ-ДД.zip`. На другом устройстве **⋯ → «Восстановить из копии»**. Тетради с такими же id заменятся версией из копии, остальные останутся. Старые копии `.json` по-прежнему восстанавливаются. Подробности в разделе «Резервная копия».
- **Автокопия:** раз в 3 дня (настраивается в **⋯ → «Автокопия»**: каждый день, раз в 3 дня, раз в неделю, выключена) приложение само скачивает `krispekt-backup-ГГГГ-ММ-ДД.zip`, если с прошлой копии что-то изменилось. Браузер может спросить разрешение на загрузку — ответь «Разрешить». Строка «Последняя копия: …» под заголовком полки становится жёлтой, если копии нет больше недели и есть несохранённые изменения.
- Копия проверяется целиком до записи: файл с ошибками или чужими данными не импортируется вовсе, а существующие тетради не трогаются.
- Очистка данных сайта или другой браузер покажут пустую полку — поэтому стоит иногда сохранять копию.

## Запуск локально

Нужен Node.js 22.13+ (LTS) и npm.

```bash
npm install        # зависимости
npm run dev        # сервер разработки: http://localhost:5173/KrisPekt/
npm test           # модульные тесты (Vitest)
npm run lint       # ESLint
npm run build      # сборка в dist/
npm run preview    # проверить сборку: http://localhost:4173/KrisPekt/
npm run test:e2e   # смоук-тест Playwright (после npm run build; первый раз: npx playwright install chromium)
```

Публикация: каждый push в `main` запускает GitHub Actions (`npm ci` → `npm audit` → lint → тесты → сборка → e2e-тесты Playwright → GitHub Pages).

### Безопасность

- Строгая Content-Security-Policy (`script-src 'self'`, `style-src 'self'`, `connect-src 'self'` …) без послаблений.
- Пользовательские данные никогда не попадают в `innerHTML`; разметка из строк — только статичные SVG-иконки.
- Резервные копии, фото и PDF считаются недоверенными: строгая проверка структуры, типов по сигнатуре файла и размеров; фото перекодируются через canvas (без EXIF/GPS); pdf.js работает без скриптов, XFA и eval.
- Данные, прочитанные из IndexedDB, тоже проверяются; повреждённые записи пропускаются.

## Резервная копия

Копия всегда один файл `krispekt-backup-ГГГГ-ММ-ДД.zip`: на планшете нет доступа к папкам, поэтому папка с файлами не подходит.

```text
manifest.json              app, format: 2, дата, версия приложения, счётчики, размер и SHA-256 каждого файла
data.json                  предметы, тетради, таблица файлов, страницы с закладками и ссылками, корзина (Deflate 9)
files/<sha256>.<ext>       фото и PDF как есть: jpg, png, webp, pdf
```

- **`data.json`.** Обычный JSON, но каждая страница на своей строке, поэтому чтение идёт по одной странице, а не целиком в память.
- **Штрихи.** Вместо координат хранятся разности соседних точек целыми числами: сначала все x, потом все y, потом нажим. Точность: координата 1/50 мировой точки (0,02), нажим 1/100. Ошибка не накапливается: каждая точка округляется сама. В `tests/e2e/backup-v2.spec.ts` страницы сравниваются по пикселям на экране 2×: при масштабе 1× заметно отличаются 0,003 % значений, при 8× — 0,03 %, и это краевые пиксели.
- **Файлы.** Одинаковые файлы хранятся один раз. Фото не сжимаются повторно. PDF сжимается, только если проба первых 256 КБ стала меньше 85 % от исходной.
- **Создание.** Части ZIP пишутся в Blob по мере готовности, с процентами и без блокировки интерфейса. Файл с неверной сигнатурой в копию не попадает, и приложение об этом предупреждает.
- **Восстановление.** Формат определяется по первым байтам, а не по имени. ZIP читается по центральному каталогу, каждый файл отдельно; общего ограничения в 300 МБ больше нет. Проверяются список имён (`manifest.json`, `data.json`, `files/<64 hex>.<ext>`), повторы, пересечения, размер и степень сжатия до распаковки, затем при распаковке реальный размер, SHA-256, сигнатура файла и вся структура данных.
- **Всё или ничего.** Сначала файлы записываются только под свободными id: существующие не затрагиваются. Затем страницы, тетради и предметы записываются одной транзакцией. При ошибке записанные файлы удаляются; если вкладку закрыли на середине, их уберёт обычная уборка неиспользуемых файлов. Файл с таким же id и другим содержимым получает новый id, а страницы копии ссылаются на него.
- **Ограничения.** ZIP до 4 ГиБ без ZIP64, до 60 000 записей, один файл до 256 МиБ, `data.json` до 2 ГиБ, одна страница до 128 МиБ, всего распаковано до 16 ГиБ, сжатие не больше 500:1 (`MAX_BACKUP_*` в `constants.ts`).
- **Старые копии.** `.json` с `app: 'krispekt'` или `'konspektnik'` читается целиком в память, поэтому для них лимит 300 МБ остаётся.

## Корзина

- Удаление предмета или тетради ставит необязательное поле `deletedAt` (у тетрадей, удалённых вместе с предметом, ещё `deletedWithSubject`). Схема IndexedDB не менялась; запись без поля считается не удалённой.
- **⋯ → «Корзина»:** дата удаления, сколько дней осталось (30), «Восстановить», «Удалить навсегда», «Очистить корзину» с общим размером.
- Предмет возвращается вместе с тетрадями, удалёнными вместе с ним. Тетрадь, удалённая раньше, остаётся в корзине. Тетрадь из удалённого предмета возвращает и сам предмет, приложение об этом сообщает. Остальные его тетради остаются в корзине.
- Через 30 дней записи удаляются при запуске и раз в час, но не пока открыта другая вкладка. Файлы освобождаются только при окончательном удалении и только если их не использует другая страница.
- Содержимое корзины не видно в поиске, выборе ссылки, недавних целях, экспорте и счётчиках полки. Ссылка на него считается битой и снова работает после восстановления. Корзина входит в копию вместе с датами.

## Хранилище и фото

- **⋯ → «Хранилище»:** занято всего (`navigator.storage.estimate` и свой подсчёт), размер предметов и тетрадей, рукопись и текст, фото, PDF, корзина, самые большие файлы с кнопкой «Открыть тетрадь». Общий файл считается один раз.
- **Новые фото:** длинная сторона до 2560 px, WebP (JPEG, если браузер не умеет WebP), качество 0,85. PNG остаётся, если он меньше: для графики и прозрачности. EXIF и геометка удаляются всегда.
- **«Сохранять исходное качество фото»** (по умолчанию выключено): полный размер и качество 0,95. Фото всё равно перекодируется, иначе метаданные остались бы в файле.
- Уже сохранённые фото не меняются; отчёт только показывает примерную возможную экономию. В векторном PDF WebP превращается в JPEG, потому что PDF не умеет хранить WebP.

## Страницы тетради

Сетка открывается кнопкой со счётчиком страниц в верхней панели. Миниатюры рисуются только рядом с видимой областью, поэтому большие тетради (200+ страниц) не тормозят.

- **Вставка:** «+» между миниатюрами, плитка «+» в конце, меню ⋮ («Вставить страницу перед/после»). Кнопка «+» в редакторе вставляет страницу после текущей.
- **Какого размера новая страница:** такого же, как страница перед ней (размер, замочек, фон). Новая страница в самом начале закреплена за размером тетради и получает фон тетради: перед ней нет страницы, с которой можно взять размер. Вставка перед любой другой страницей равна вставке после предыдущей.
- **Перенос:** пальцем или стилусом — удержать и перетащить, мышью — сразу перетащить. У края список прокручивается сам. Отпустить вне сетки или нажать Escape значит отменить. Удержать и отпустить — открыть меню. То же есть в меню ⋮: раньше, позже, в начало, в конец.
- **Смена первой страницы:** размер тетради хранится в ней самой и не зависит от порядка страниц. Перенос и удаление не меняют размер ни одной страницы: закреплённые остаются в размере тетради, страница со своим размером сохраняет его, даже став первой.
- **Сохранение:** страницы и их порядок пишутся одной транзакцией IndexedDB. При сбое остаётся либо старое состояние, либо новое, страницы не теряются и не задваиваются.
- **Удаление:** одной страницы из меню, нескольких — через «Выбрать». Сначала подтверждение с числом страниц, затем примерно 6 секунд кнопка «Отменить», которая возвращает страницы, содержимое и позиции.
- **Последнюю страницу удалить нельзя:** у тетради всегда есть хотя бы одна страница. Если выбраны все страницы, появится подсказка, и ничего не удалится.
- **Дублирование:** копия появляется сразу за оригиналом и повторяет штрихи, текст, картинки, фон PDF, размер и замочек. Файлы картинок у копии и оригинала общие; удаление одной из страниц их не затрагивает.
- **Отмена и повтор:** шаги кнопок «Отменить/Повторить» привязаны к странице, а не к её номеру, поэтому вставка, перенос и дублирование их не сбивают и сами шагами не считаются. Шаги удалённой страницы стираются целиком; у страницы, возвращённой через «Отменить», ранних шагов нет. Шаг, который охватывал несколько страниц, стирается целиком, а не наполовину. Перед любой операцией завершается ввод текста и снимается выделение лассо.
- **Файлы картинок удалённых страниц:** записи страниц удаляются сразу, а файлы — только после окна отмены. Если приложение закрыли раньше, уборка пройдёт при следующем запуске. Файлы, на которые ещё ссылается страница, шаг отмены или страница в окне отмены, не удаляются. Если приложение открыто в другой вкладке, уборка откладывается: та вкладка может использовать файл, на который ещё нет сохранённой ссылки.

## Стирание зачёркиванием

Если ручкой зачеркнуть написанное зигзагом, не отрывая перо, зачёркнутое удаляется. Распознавания почерка нет, решает только геометрия. Настройка: ⋯ → «Стирать зачёркиванием» (вкл./выкл. и чувствительность). Настройки лежат в `konspektnik.prefs.v1` в необязательном поле `scratch` и проверяются при загрузке.

- **Форма.** Смотрим направление движения пера и считаем развороты: разворот считается, только если перо вернулось назад минимум на половину длины штриха. Плотность — это длина пути на размер штриха. Шаг — сдвиг вбок на один проход: он отличает зигзаг от «www», «ммм» и «ш». Закрутка отличает зигзаг от слова, обведённого в несколько кругов.
- **Что закрыто.** Выпуклая оболочка зачёркивания плюс четверть её меньшей стороны. Штрих удаляется, если внутри не меньше 60 % его длины. Символ текста — если внутри не меньше 60 % его рамки; если закрыто от 60 % букв слова, оно уходит целиком вместе с пробелом. Пустой текстовый блок удаляется.
- **Не трогается.** Картинки и фон страницы, другие страницы. Маркер и ластик этого не умеют, линии по линейке и выпрямленные удержанием тоже не считаются. Если удалять нечего, зачёркивание остаётся обычным штрихом.
- **Отмена.** Одно действие: всё возвращается, а само зачёркивание нет.
- **Диагностика.** Долгое нажатие на «Рисовать пальцем» в ⋯ показывает числа последнего штриха, их пределы и решение.
- **Ограничения.** Слово, написанное одним штрихом, удаляется только целиком: штрихи не режутся на части. Редкий зигзаг по форме совпадает с узким «www», поэтому при обычной чувствительности остаётся штрихом. Круговое зачёркивание на месте считается обводкой. Плотная штриховка поверх записей считается зачёркиванием.

## Панель инструментов

- **Наборы.** Набор — это инструмент с настройками: тип ручки, цвет, толщина; маркер; ластик; текст. В настройках инструмента есть кнопка «Закрепить на панели», всего можно закрепить до 12 наборов. Пока набор выбран, любое изменение настроек сохраняется в нём. Обычные инструменты при этом свои настройки не меняют.
- **Касания.** Касание невыбранного инструмента или набора выбирает его. Касание выбранного открывает настройки. Исключение — ластик: касание выбранного ластика, как и раньше, переключает его режим. Долгое нажатие открывает настройки обычного инструмента, а у набора — меню «Настроить, Дублировать, Открепить».
- **Настройка.** ⋯ → «Настроить панель», или долгое нажатие на саму панель между кнопками, или кнопка внизу окна «Другие инструменты». Кнопки двигаются за ручку или стрелками, глаз скрывает их. Все изменения сохраняются сразу. Скрыть нельзя отмену, повтор и последнее, чем можно писать. Кнопка «Другие инструменты» всегда стоит последней. Сброс возвращает порядок и показывает всё скрытое, закреплённые наборы остаются.
- **Когда не хватает места.** Кнопки, которые не поместились, уходят в окно «Другие инструменты», сначала самые неважные: фото, линейка, цвета, затем инструменты. Отмена, повтор, кнопка «Другие инструменты» и выбранный инструмент всегда на панели. Если выбрать инструмент из этого окна, он встаёт на панель, пока выбран, а место ему уступает другая кнопка.
- **Хранение.** Наборы и порядок кнопок лежат в настройках (`konspektnik.prefs.v1`) и проверяются при загрузке: неверные записи отбрасываются, остальные настройки не страдают. В резервную копию они не входят, как и другие настройки: копия хранит конспекты, а панель настроена под конкретное устройство. Старые копии подходят без изменений.

## Вложения: PDF и ссылки

В ⋯ → «Вставить» (или кнопкой со скрепкой на панели) можно положить на страницу карточку с PDF-файлом или веб-ссылкой, а в текстовом блоке сделать ссылкой слово.

- **Карточка.** Отдельный элемент страницы: двигается лассо, меняет ширину, отменяется, попадает в экспорт и резервную копию. Ластик и зачёркивание её не трогают, «Очистить страницу» тоже: удаляется только через её меню или лассо.
- **PDF.** До 50 МБ, принимается по подписи `%PDF-`, а не по имени или типу файла. Хранится один раз, сколько бы карточек на него ни ссылалось (id из SHA-256 содержимого). Файл удаляется уборкой, когда на него не ссылается ни страница, ни шаг отмены. Просмотрщик только рисует страницы: ни скрипты, ни формы, ни ссылки из файла не работают, показывается не более 500 страниц.
- **Ссылка.** Только `http:` и `https:`, не длиннее 2048 символов, без логина и пароля в адресе; те же проверки при чтении копии и перед самым открытием. Перед переходом всегда показывается адрес. Ничего не скачивается заранее: ни заголовков, ни значков сайтов.
- **Модель.** Ссылка в тексте хранится в поле `link: { kind: 'url', href }` у фрагмента текста. Другие виды ссылок смогут использовать это же поле.
- **Резервная копия.** PDF входит в неё целиком, отдельным файлом. Текущий размер копии показан рядом с настройками.

## Закладки и внутренние ссылки

Закладка отмечает место в записях: выделение лассо, текстовый блок или его часть, целую страницу. Ссылка ведёт на закладку, страницу или тетрадь; её можно поставить на слово в текстовом блоке или на рукописный текст (лассо → кнопка ссылки).

- Ссылки хранят идентификаторы, а не номера, поэтому перестановка и вставка страниц их не ломают.
- Закладка на выделение двигается вместе со своими элементами. Если её элементы удалены, закладка исчезает вместе с ними, а ссылки на неё становятся битыми; отмена возвращает всё сразу.
- Дублирование страницы копирует закладки **с новыми идентификаторами**, поэтому существующие ссылки продолжают вести на оригинал. Копирование лассо закладки не копирует, а рукописные ссылки копирует.
- Битая ссылка показана красным с пунктиром; нажатие сообщает, что цель удалена, и предлагает убрать ссылку.
- «Назад» помнит до 20 переходов. Системная кнопка «назад» на Android сначала проходит по ним. Адрес страницы при этом не меняется.
- История отмены каждой тетради сохраняется при переходах по ссылкам и сбрасывается при выходе на полку, как и раньше.
- Векторный PDF: ссылки на страницы и закладки той же тетради становятся переходами внутри файла (если страница попала в экспорт). Ссылки на другие тетради выглядят как ссылки, но не нажимаются. В растровых форматах ссылки не нажимаются. Значки закладок ни в какой экспорт не попадают.
- Резервная копия: закладки и ссылки входят в неё и проверяются при импорте. Восстановление обновляет записи по их идентификаторам, идентификаторы не меняются, поэтому ссылки остаются верными и переназначать их не нужно. Старые копии импортируются без изменений. Схема IndexedDB не менялась.
- Скопированная внутренняя ссылка хранится только в памяти приложения и не попадает в системный буфер обмена.

## Текстовые блоки

- **Размер.** Новый блок маленький и растёт вправо, пока вы пишете. У правого поля страницы текст переносится, и блок растёт вниз. Если потянуть за край, ширина становится постоянной. Высота всегда подстраивается под текст. Пустой блок при выходе удаляется.
- **Касания.** Касание страницы создаёт блок. Касание блока выделяет его (рамка, ручки, панель). Второе касание ставит курсор. Боковые и угловые ручки меняют ширину, блок двигается за значок над рамкой или за сам текст. Зона касания ручек не меньше 44 пикселей при любом масштабе.
- **Оформление** относится к выделенным буквам, а если блок только выделен, то ко всему блоку: размер, жирный, курсив, подчёркивание, зачёркивание, цвет, выравнивание, списки. Последний выбранный стиль становится стилем новых блоков.
- **Лассо.** Блок попадает в выделение, если в петле оказалась середина видимого текста, а не середина рамки. Выделенное можно двигать (и на другую страницу), удалять, копировать и вставлять. Каждое такое действие отменяется одним шагом.
- **Курсив.** У шрифта Onest нет курсивного начертания, поэтому курсив везде получается наклоном букв: на экране и в PDF. Жирный — настоящее начертание, в PDF встроены оба файла шрифта, текст там можно выделять.
- **Отмена.** Пока блок редактируется, отмена работает внутри него: подряд набранное слово — один шаг, пауза больше секунды или конец слова начинают новый. После выхода из блока всё редактирование — один шаг отмены страницы.
- **Данные.** Текст хранится абзацами и кусками со стилем, не HTML. Вставка из буфера всегда превращается в обычный текст. Старые блоки выглядят как раньше и меняются, только когда их правят. Версия базы данных та же, старые резервные копии подходят.

## Выделение и масштаб

- **Перенос между страницами:** выделение лассо при перетаскивании рисуется без обрезки по своей странице. При отпускании оно попадает на страницу под центром своей рамки (если центр в промежутке — на ближайшую), координаты пересчитываются, а группа сдвигается (не масштабируется) внутрь страницы; группа больше страницы прижимается к левому верхнему углу. Так же сдвигаются перенос и изменение размера в пределах страницы и копия из панели выделения. Перенос на другую страницу — один шаг отмены, который восстанавливает обе страницы.
- **Починка при открытии:** объекты, которые старые версии оставили целиком за краем страницы, при открытии тетради сдвигаются обратно на страницу и сохраняются. Их число видно в диагностике ввода.
- **Масштаб:** при щипке (и Ctrl + колесо) растягивается готовая картинка страницы, но только если она показывает текущее содержимое (ревизия страницы и скрытые объекты совпадают). Иначе страница один раз перерисовывается в пониженном разрешении, а по окончании щипка — в полном. С 300 штрихами при замедлении процессора в 4 раза кадр щипка в среднем 17–25 мс (`tests/e2e/pinch-performance.spec.ts`).
- **Щипок и прокрутка двумя пальцами:** два пальца меняют масштаб, только когда расстояние между ними изменилось больше чем на `PINCH_ZOOM_SLOP_PX` (20 px) и хотя бы на половину пути, пройденного ими вместе. Иначе это прокрутка, и масштаб не «плывёт».
- **Закрепление масштаба:** кнопка с процентами открывает меню: текущее значение, «Вписать по ширине», 100 % и закрепление (оно же есть в ⋯, потому что на телефоне кнопка скрыта). Пока масштаб закреплён, щипок только сдвигает страницу, Ctrl + колесо не действует, а масштаб не меняется при прокрутке, переходе на страницу другого размера и изменении размера окна. Пункты «Вписать по ширине» и 100 % в это время отключены, а не снимают закрепление сами: случайное нажатие не должно его сбрасывать. Единственное место записи масштаба — `Camera.setZoom`, поэтому закрепление действует на любой путь изменения.
- **Где хранится:** необязательное поле `zoomLock` в записи тетради; его нет — значит, масштаб не закреплён. Схема IndexedDB не менялась, старые записи работают как раньше. Поле выбрано вместо настроек, потому что так закрепление само попадает в резервную копию и удаляется вместе с тетрадью. При импорте значение проверяется: только число в пределах от `ZOOM_MIN` до `ZOOM_MAX`.
- **Сохранение вида:** страница и масштаб запоминаются и при уходе приложения в фон, а не только при выходе кнопкой «назад», поэтому Android может закрыть приложение без потери масштаба.

## Экспорт

Пункт «Экспорт…» есть в ⋯ тетради на полке и в ⋯ редактора. Последний выбор запоминается.

- **PDF (вектор, по умолчанию):** штрихи, фоны (клетка, линейка, точки) и текст — векторные пути и настоящий текст, поэтому PDF чёткий при любом увеличении, текст выделяется и ищется, а файл обычно намного меньше (пример тетради: 21 КБ вместо 683 КБ у прежнего экспорта картинками). Экран и PDF рисуются из одних и тех же команд (`src/canvas/draw/`): кисти, раскладка текста и фоны выдают команды, а `Canvas2DBackend` и `PdfVectorBackend` их исполняют. Текст набирается шрифтом Onest, который встраивается подмножеством только нужных букв; файл шрифта загружается с нашего же сайта только при экспорте. Фото и страницы из PDF встраиваются в сохранённом разрешении, без пережатия. Что отличается от экрана: маркер в PDF рисуется под всеми чернилами с прозрачностью 0,55 (jsPDF не умеет режим наложения «умножение»), а зерно карандаша заменено ровным тоном той же средней плотности.
- **Растровый PDF:** каждая страница — PNG без потерь на 300 или 600 dpi.
- **PNG:** 2×, 4× (по умолчанию) или 6× от размера страницы при 96 dpi (A4 в 4× — 3175 × 4490 пикс.), с бумагой и фоном или без фона (прозрачный; фон-страница из PDF остаётся). Файлы называются `<тетрадь>-p<N>.png`; несколько страниц сохраняются одним `<тетрадь>-png.zip` (библиотека fflate, загружается только при сборке ZIP).
- **Память:** страница больше 40 Мп (огромный формат на 600 dpi или 6×) рендерится с меньшим разрешением, об этом сообщает всплывающее сообщение.

## Отсечение ладони

Логика — в чистом классе `src/domain/TouchClassifier.ts` (покрыт тестами), `InputRouter` только выполняет его решения. Пороги — в `src/core/constants.ts`.

- **Размер касания:** касание шире или выше `PALM_SIZE_PX` (28 CSS px) — ладонь до самого отрыва; размер перепроверяется на каждом движении, палец, «расплывшийся» в ладонь, сразу перестаёт листать.
- **Сессия письма:** любое событие стилуса (касание, движение, наведение) продлевает её на `PEN_SESSION_MS` (1,5 с). Пока она идёт, один палец не листает и не рисует; масштаб и сдвиг двумя пальцами работают.
- **Отложенное листание:** один палец начинает листать, только сдвинувшись больше чем на 10 px и не раньше чем через 80 мс; если раньше пришло событие стилуса, это ладонь.
- **Откат:** если стилус коснулся экрана во время листания одним пальцем или в течение 700 мс после него, страница возвращается туда, где была, инерция останавливается.
- **Три и больше касаний** — ладонь или хват: игнорируются, пока не будут подняты все.
- Двумя пальцами отмена не срабатывает, если стилус был активен меньше 1 с назад или одно из касаний — ладонь. Линейка тоже не реагирует на ладонь.
- **Если устройство сообщает размер 1×1:** `TouchSizeProbe` берёт размер из `Touch.radiusX/radiusY` (пассивные слушатели `touchstart/touchmove` только запоминают размеры, ввод по-прежнему обрабатывают Pointer Events). `pointerdown` приходит раньше `touchstart`, поэтому такой размер известен с первого движения.

**Диагностика ввода:** в редакторе ⋯ → долгое нажатие на «Рисовать пальцем». Внизу слева появляется список последних событий указателя: тип, id, размер `ш×в` (`*` — размер из TouchEvent), нажим, кнопки, событие, как оно классифицировано (`pen` / `finger` / `palm` / `ignored` и роль касания) и `✎`, если шла сессия письма. Если при открытии тетради были возвращены объекты из-за края страницы, их число показано в заголовке. Ничего не сохраняется и не уходит с устройства; повторное долгое нажатие выключает.
